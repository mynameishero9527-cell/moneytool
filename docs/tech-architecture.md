## 2. 总体架构

一个 Python 进程内跑四件事：调度器、数据接入、计算、Web 服务。存储是本地文件。

```text
python -m moneytool
   │
   ├─ APScheduler（进程内）
   │     ├─ 盘前同步 / 竞价 / 5 个分段 / 收盘全量 / 夜间参考数据 / 事后统计
   │
   ├─ 接入层  adapters/
   │     ├─ eastmoney   资金流（日 + 今日实时）、日线、板块与概念成分、涨跌停、竞价分时
   │     ├─ shenwan     申万一级 / 二级成分与指数行情
   │     ├─ csindex     中证与交易所指数成分
   │     ├─ baostock    日线复权因子备份、交易日历
   │     ├─ cninfo      公告（减持、处罚、股东户数）
   │     ├─ external    外盘期货、海外指数、汇率
   │     └─ hkex        北向公开披露
   │
   ├─ 计算层  compute/
   │     资金流分段差分 → 指标派生 → 板块阶段 → 个股角色 → 名单动作 → 指数与提示 → 存档 → 简报
   │     参数版本（YAML）│ 规则引擎（证据输出）│ 盘中增量 / 收盘全量 │ 价格模式降级
   │
   ├─ 存储  data/
   │     ├─ moneytool.duckdb        全部结构化数据
   │     ├─ raw/{source}/{date}/    原始响应 Parquet，只追加，保留 90 天
   │     ├─ params/{version}.yaml   参数版本
   │     ├─ briefs/{date}.md        每日简报
   │     ├─ backups/                export 产物，保留最近 5 份
   │     └─ .lock                   重算 / 回补互斥锁
   │
   └─ Web 服务  FastAPI + uvicorn
         ├─ /api/...               查询、回看、事后统计、口径
         └─ /                      静态前端（Vue 3 + ECharts，已打包 JS 随包分发）
```

层之间只通过 DuckDB 表通信。计算层不直接调接口；前端不算指标。

## 3. 数据源

### 3.1 唯一资金口径：东方财富

东方财富的资金流接口同时提供历史日频和「今日」实时累计，分档一致（超大单、大单、中单、小单，主力 = 超大 + 大），且个股与板块（行业、概念）同源。这是免费源里唯一能满足需求 6 节「一个口径」的选择。

| 数据 | AkShare 接口 | 频率 | 用途 |
| --- | --- | --- | --- |
| 个股今日实时资金流（全市场一次拉取） | `stock_individual_fund_flow_rank(indicator="今日")` | 盘中每分段末拉 1 次 | 分段差分 |
| 板块今日实时资金流（行业 / 概念） | `stock_sector_fund_flow_rank(indicator="今日", sector_type=...)` | 同上 | 板块分段差分与对账 |
| 个股历史日频资金流 | `stock_individual_fund_flow(stock, market)` | 收盘后；首次回补 | 日频序列 |
| 板块历史日频资金流 | `stock_sector_fund_flow_hist(symbol)` | 收盘后 | 板块日频 |
| 大盘资金流 | `stock_market_fund_flow()` | 收盘后 | 市场层 |

**分段差分**：每个分段结束后拉一次「今日」全市场累计值，本段净流入 = 本次累计 − 上次累计。竞价段单独用 9:25 后第一次拉取。收盘后再用日频接口拉当日正式值，与 5 段之和对账，偏差写进数据质量表。

**对账**：需求 6 节要求不混口径，这里所有资金数字都来自东财，对账只是东财实时值和东财日频值之间的自检，不引入第二家。

### 3.3 免费源的使用纪律

免费接口的主要风险是限流、滑块验证、字段变更。设计上用这几条对付：

- **低频**：资金流用全市场排名接口，一次调用拿全部股票，每个分段只调 3 次（个股、行业、概念）。全天资金流相关调用不超过 30 次。个股级接口（历史资金流、日线回补）只在首次回补和夜间补缺时用，且串行、带间隔。
- **只追加缓存**：每次响应原样落 Parquet 到 `raw/`，同一交易日同一接口已有成功响应就不再请求。回补失败可以断点续传。
- **限速与退避**：每个源一个令牌桶（东财默认 1 次 / 2 秒，个股级接口 1 次 / 5 秒），失败按 10s、30s、90s 退避，三次失败标「数据缺失」，当日不再重试，夜间任务补。
- **字段契约**：每个适配器有一份期望列名与类型的契约，响应不匹配立即报错并保留原始响应，不让脏数据进计算。AkShare 升级后先跑契约测试。
- **备选源只用于非资金数据**：日线、复权、日历可以切 Baostock；资金流不切，缺就缺，按需求 11.3 标「数据缺失」。
- **手工兜底**：命令行提供 `moneytool fetch --date 2026-09-24 --source eastmoney.flow` 手工重拉；遇到滑块验证时提示用户在本机浏览器打开东财一次（同 IP 验证后接口通常恢复）。

## 4. 计算层

### 4.1 八步顺序

```text
① 资金流整理      分段差分、日频正式值、板块聚合校验、一字板剔除（8.1）
② 指标派生        6.1 全部派生量，Polars 列运算
③ 市场风控        7.6 市场情绪压力指数分项 → 风控开关 risk_gate（读昨日 confirmed 决定持续 / 关闭）
④ 板块阶段        7.1 六阶段 + 优先级 + 防抖 + 迁移路径；7.2 形态；7.5 归因；7.3.1 主线与轮动
⑤ 个股角色        8.1 / 8.2 / 8.6 / 8.10 / 8.7
⑥ 名单与动作      8.3 / 8.4 / 8.8 / 8.9、跟踪闭环；8.3 条件 9 读 risk_gate
⑦ 指数与提示      7.7 板块情绪 / 风险；8.11 个股风险 / 散户承接压力 / 持有结构评估；模板化分析提示
⑧ 存档与简报      按 trade_date + param_version 写 confirmed 表；盘中写 intraday 表；收盘确认后生成简报
```

③ 放在板块阶段之前，因为 risk_gate 是名单步骤的输入；⑦ 放在名单之后，因为个股风险指数、持有结构评估要读当日角色和名单结果，且指数不反向影响名单（8.11 明确风险指数 ≥ 80 只影响展示顺序）。

### 4.1.1 指数与提示的实现约束

- 五个指数各由 5 个分项组成，每项 0–20，分项值 = 该项在 250 日分位上的线性映射；公式与列名在 `capital-flow-indicators` skill 中，代码只实现一次 `percentile_score(series, window=250) -> 0..20`。
- 历史不足 250 日时，指数输出 `null` 并标「历史不足」，不用短窗口顶替。
- 分项与总分都落 `index_daily` 表，前端仪表盘直接读分项，不在前端重算。
- 持有结构评估三态（`HoldEval.INTACT / REVIEW / BROKEN`）是纯规则，输入为个股角色行 + 名单行 + 昨日评估，输出附证据。
- 分析提示：`hints/templates/*.yaml` 存句式，每条模板声明所需证据键；`render_hint(template_id, evidence) -> Hint(text, links[])`，缺证据键则不渲染该条而不是留空占位。模板文本进入第 12 节禁用词检查，测试里对全部模板跑一次。
- 指数、评估、提示都是 ⑦ 的纯函数，可以按日重算而不触碰名单。

### 4.1.2 降级：价格模式

需求 11.4。当东财资金流当日全部缺失（分段与日频都失败），计算链不中止，按下表执行：

| 步骤 | 价格模式行为 |
| --- | --- |
| ① | 跳过；`flow_daily` 当日无行，`data_quality` 记 `DEGRADED` |
| ② | 只算价格、成交额、换手、广度类派生量；资金流派生量为 `null` |
| ③ | 只用不依赖资金流的分项，指数标「降级」 |
| ④ | 阶段沿用昨日 confirmed 并标「沿用」，不做迁移判定 |
| ⑤ ⑥ | 不新增买入关注 / 低位企稳；卖出关注只触发「结构破坏」与「跟踪期满」两类 |
| ⑦ | 资金流分项为 `null`，总分按可用分项等比缩放并标「降级」 |
| ⑧ | 正常存档，`data_status = DEGRADED`；简报首行写明降级 |

资金流恢复后，`recompute --date` 对降级日重算，旧快照保留。

### 4.1.3 重算与回补的互斥

`recompute`、`backfill`、调度器的收盘全量共用一个写连接，且不能并发。实现用文件锁 `~/.moneytool/.lock`（`filelock` 库）：

- 调度线程在任务开始时取锁，结束释放。
- 命令行 `recompute` / `backfill` 先探测主进程是否在跑（`/api/status` 可达）；在跑则通过 HTTP `POST /api/admin/recompute` 交给主进程排队执行，不直接开写连接；不在跑则自己取锁执行。
- 锁被占用时命令行等待最多 60 秒后报错退出，提示当前持有者与开始时间。

### 4.2 规则引擎

- 每条规则是纯函数：输入某日某标的的指标行与参数，输出 `{hit, evidence[]}`。证据结构固定：规则名、指标名、当日值、阈值、是否命中。
- 阶段判定输出所有候选的命中情况，再按 7.1 优先级取最终阶段，被压下的候选进解释区。
- 防抖读昨日 confirmed 表，不读内存。
- 阈值全部在 `params/{version}.yaml`，逻辑在代码。需求 6.2、6.3、8.10 等所有阈值都在这一份文件里。
- 测试：需求 14 节 47 条验收标准每条一个测试，用构造的指标行；另选 5 个历史交易日做金样本，改规则先跑金样本比对。
- 风控开关对规则引擎只是参数行里的一个布尔列 `risk_gate`，规则不知道它怎么算出来的。

### 4.3 参数版本

- `params/` 目录下每个版本一个 YAML，文件名即版本号，含生效交易日与变更说明。
- 计算时按交易日取当日生效版本，版本号写进每条结果。
- 只新增文件，不改旧文件。事后统计按版本分组。
- 参数调优（需求 6.4）的工具支持：`moneytool recompute --dates <file> --params <version>` 对一组日期按指定版本重算到临时 schema（`tuning_<version>`），不覆盖 confirmed；`moneytool params compare <v1> <v2> --dates <file>` 输出名单长度、重叠率、事后统计对比表。调优日期集与验证日期集是两个文件，随 `params/` 一起进仓库。

### 4.4 盘中与收盘

| 模式 | 触发 | 输入 | 输出 |
| --- | --- | --- | --- |
| 竞价 | 9:26 | 盘前分时 | 盘前倾向 |
| 盘中增量 | 10:31、11:31、14:01、14:31、15:01 | 今日累计资金流差分 + 历史 confirmed | `*_intraday`，标 segment |
| 收盘全量 | 15:30 起，等东财日频资金流与日线到位（通常 18:00–19:00 前齐） | 当日正式值 + 历史 | `*_confirmed`，触发提醒确认 / 撤销 |

东财日频资金流的正式值通常在收盘后数小时才齐，所以收盘全量任务从 15:30 开始每 30 分钟探测，数据齐了就跑，最晚 20:00 用最后一次实时累计值代替并标「未经日频对账」。这一点要在口径页写明，与需求 13「晚间复盘前可用」一致。

全市场约 5000 只、一级 31、二级约 130、概念数百。Polars 单机全量计算在一分钟内，不需要并行框架。

### 4.5 首次启动回补

第一次运行时没有历史，需要回补：

| 数据 | 范围 | 来源 | 说明 |
| --- | --- | --- | --- |
| 日线 + 复权 | 5 年，全 A | Baostock（批量友好） | 归因与低位企稳需要 |
| 个股日频资金流 | 2 年，全 A | 东财 `stock_individual_fund_flow` | 接口按股票返回全部历史，逐只调用约 5000 次，串行带间隔；分多晚完成，UI 显示进度；先回补候选名单和自选股，再补全市场 |
| 板块日频资金流 | 5 年 | 东财 `stock_sector_fund_flow_hist` | 板块数少，一晚可完成 |
| 申万成分 | 当前 + 每日快照起点 | 申万 | 历史变更免费源不完整，从首次运行日开始积累；回看首次运行日之前的日期用当前成分并标「成分为近似」 |
| 指数成分 | 当前，含纳入日期 | 中证 | 纳入日期可反推部分历史 |
| 概念成分 | 当前 | 东财 | 同申万，从首次运行日开始积累 |
| 股东、减持、处罚 | 3 年 | 东财、巨潮 | 只对进入候选名单的股票按需拉，不全市场回补 |

回补是可中断可续跑的后台任务，进度写表，前端「数据状态」页可见。回补未完成时，依赖长历史的功能（归因、低位企稳、事后统计）显示「历史不足」，其余功能可用。

## 5. 存储

### 5.1 选型

| 用途 | 选型 | 理由 |
| --- | --- | --- |
| 全部结构化数据 | DuckDB 单文件 | 嵌入式、零运维、列式分析快、Polars 零拷贝互通、支持直接查 Parquet |
| 原始响应 | Parquet 按源按日 | 只追加、可重放、可删可重建 |
| 参数版本 | YAML 文件 | 可读可 diff，随代码仓库管理 |
| 用户数据（自选、提醒记录、设置） | DuckDB 同一文件内独立表 | 单用户本地，不需要另一套 |

不用 Redis：提醒去重用 DuckDB 表 `alert_log` 按（日期、标的、事件）唯一约束实现；限频在进程内计数。不用消息队列：调度和计算在同一进程，直接函数调用。

DuckDB 是单写者。进程内用一个写连接归调度线程，Web 请求用只读连接，并发读写安全。

### 5.3 备份、升级与保留

- `moneytool export --out backups/2026-09-24.zip`：DuckDB `EXPORT DATABASE` 到 Parquet + `params/` + `config.toml` 打包；`moneytool import <zip>` 反向恢复到空数据目录。夜间任务每周日自动 export 一次，保留最近 5 份。
- DuckDB 文件格式随版本变化，升级 DuckDB 依赖前必须在 CI 里用上一版 export 产物做 import 演练；`release-packaging` skill 的检查单包含这一项。
- 保留策略：`raw/` 原始响应 90 天（`flow_*` 表已是结构化结果，重放窗口 90 天足够）；日志 30 天；`backups/` 最近 5 份；结构化表不删。清理在夜间任务末尾执行，删前写 `data_quality` 一条记录。

单用户一年数据量：`flow_intraday` 约 5000 × 250 × 6 ≈ 750 万行，`feature_daily` 略多。DuckDB 单文件在几 GB 量级，普通笔记本可跑。

## 6. Web 服务

- FastAPI + uvicorn，进程内启动，默认 `127.0.0.1:8000`，启动后自动打开浏览器。
- 接口分组：市场总览（含情绪压力与风控开关）、板块（列表 / 详情 / 对比 / 资金流向图）、个股（含指数、持有结构评估、提示）、行动清单与手工标记、自选分组与提醒、回看、事后统计、简报、口径与参数、数据状态、搜索、管理（`/api/admin/recompute` 等，只接受回环地址）。
- 所有查询接口接受 `trade_date`，缺省为最近交易日；有值即回看，读 confirmed 表。盘中另有 `segment`。
- 每个数字带口径元信息：估算 / 已确认 / 盘中 / 未经对账 / 降级、参数版本。全站响应头带 `X-Data-Status`（需求术语表 `DataStatus`），前端据此渲染顶部横幅。
- 搜索 `/api/search?q=`：代码、名称、拼音首字母（`pypinyin` 生成，随 `security` 表存一列）三路匹配，返回前 20。
- 启动时校验本机时钟与交易所时间：向东财行情接口取服务器时间戳，偏差 > 2 分钟在数据状态页与日志警告，不阻止启动；分段任务按本机时钟触发，因此这项警告要醒目。
- 提醒：计算任务完成后写 `alert_log`，前端轮询拉取；可选桌面通知（`plyer`）和一个 Webhook（企业微信 / 飞书 / 钉钉之一，配置文件填 URL）。不做邮件。
- 无鉴权：只监听本机回环地址。若用户配置监听 `0.0.0.0`，启用简单 Token。

## 7. 前端

- Vue 3 + TypeScript + ECharts + TanStack Table，Vite 构建。构建产物 `frontend/dist/` 拷入 Python 包的 `moneytool/static/`，随 wheel 分发；FastAPI 用 `StaticFiles` 托管，`/` 返回 `index.html`。用户只需 Python，不装 Node；开发者构建时需要 Node 20+。
- 开发模式：`vite dev` 起在 5173，代理 `/api` 到 8000；生产模式只有一个 Python 进程。
- 仓库里 `frontend/` 与 `moneytool/` 并列；`make build` 或 `python scripts/build_frontend.py` 一键构建并拷贝；CI 校验 `static/` 与 `frontend/` 源码一致。
- 页面与需求 10 节一致：看板、多板块对比、板块详情、个股页、行动清单、自选、回看与事后统计、口径与说明，另加「数据状态」页显示回补进度、当日缺失、对账偏差。
- 证据卡片组件统一渲染规则引擎的 JSON 证据，新增规则前端不用改。指数仪表盘组件同理：读 `index_daily` 的 5 个分项与总分统一渲染，五个指数共用一个组件。
- 分析提示组件只渲染后端已拼好的文本与链接，前端不含任何句式模板。
- 键盘导航与搜索（需求 10 节）：全局 `/` 聚焦搜索，`Esc` 关闭，`←` `→` 切换交易日，`g b` / `g a` 跳转看板 / 行动清单，用一个 `useHotkeys` 组合式函数集中注册。
- 盘中：分段结束后前端轮询一次 `/api/status`，有新 segment 就刷新，不用 WebSocket。
- 端到端测试：Playwright 跑在构建产物 + 一个装了固定金样本数据目录的 Python 进程上，覆盖需求 14 节里涉及页面的验收条（7、13、33、35、38、40、41、44）；CI 每次 PR 跑，约 3 分钟。

## 8. 调度

APScheduler 进程内运行，任务依赖用显式串联而不是依赖图，因为单机顺序执行足够。

```text
08:00  启动自检：时钟偏差、各源连通性、昨日 confirmed 是否存在（缺则补跑）
08:25  参考数据同步：日历、停复牌、ST、申万与概念成分快照、涨跌停价
08:30  盘前简报生成 → 推送（静默期 20:30–08:30 结束后的合并提醒一并发出）
09:26  竞价段 → 盘前倾向
10:31 / 11:31 / 14:01 / 14:31 / 15:01
       拉今日累计资金流（个股、行业、概念各 1 次）→ 差分 → 盘中增量计算（含市场风控）→ 提醒
15:30 起每 30 分钟探测东财日频资金流是否到位 → 到位即收盘全量 → 存档 → 提醒确认 / 撤销 → 收盘简报生成与推送
       最晚 20:00 用实时累计值代替并标「未经对账」；资金流全缺则按价格模式跑
20:30  夜间：补缺、对账偏差记录、季频与公告数据（仅候选名单相关股票）、排除标签重算
21:00  事后统计补齐
21:30  保留策略清理；周日另做自动 export
```

- 非交易日不触发。临时休市在配置文件里加日期。
- 提醒静默期 20:30–08:30：期间产生的提醒只写 `alert_log`，不推送，盘前简报合并发出；风控开关变化例外，立即推送。同板块 ≥ 3 条提醒合并为一条。
- 程序未运行时错过的任务：启动时检查最近交易日 confirmed 是否存在，缺则补跑收盘全量（用日频接口，数据齐全）；错过的盘中分段不补，标「未采集」。
- 分段拉取失败：该段标「数据缺失」，下一段差分以上一次成功值为基准，并在 UI 标出跨段。

## 9. 安装与运行

- Python 3.11+，`pip install moneytool` 或 `uv tool install moneytool`；依赖：akshare、baostock、polars、duckdb、fastapi、uvicorn、apscheduler、pyyaml、httpx、filelock、pypinyin。
- 首次运行 `moneytool init`：创建 `~/.moneytool/`（或 `--data-dir` 指定），写默认配置与参数版本 v1，启动回补任务；首页显示首次运行向导（需求 9.10）。
- 日常 `moneytool run`：启动调度与 Web，打开浏览器。可加 `--no-browser`、`--port`。
- 辅助命令：`moneytool fetch`（手工拉取）、`moneytool recompute --date | --dates <file> [--params <version>]`（重算，见 4.1.3 互斥与 4.3 调优）、`moneytool backfill`（续跑回补）、`moneytool params new | compare | explain`、`moneytool export | import`（备份恢复，见 5.3）、`moneytool brief --date`（手工生成简报）、`moneytool doctor`（检查各源连通性、契约、时钟偏差、锁状态）。
- 性能基准 `scripts/bench.py`：用金样本数据目录跑一次完整收盘全量，输出各步耗时；CI 记录趋势，任一步超过上次 1.5 倍则失败。目标仍是整链 1 分钟内。
- 配置文件 `config.toml`：数据目录、监听地址、Webhook URL、限速参数、临时休市日期。
- 需要电脑在交易时段开机且联网；睡眠会错过分段，启动时按上文补收盘。
- 跨平台：Windows、macOS、Linux 均可，无原生依赖。
- 日志写 `~/.moneytool/logs/`，按日滚动。

## 12. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 东财限流 / 滑块验证 / 封 IP | 盘中分段缺失 | 全市场一次拉取、每段仅 3 次调用、令牌桶限速、失败退避；提示用户浏览器过一次验证；缺失按需求标记不填补 |
| AkShare 接口字段变更或失效 | 采集中断 | 契约测试；固定 AkShare 版本，升级前跑 `doctor`；原始响应落盘便于事后重解析 |
| 东财日频正式值到得晚 | 收盘确认延迟 | 15:30 起探测，最晚 20:00 用实时累计值并标「未经对账」 |
| 免费源没有严格自由流通股本 | 换手与市值口径偏差 | 用流通股本近似，口径页写明；控盘风险的 30 亿线按流通市值执行 |
| 成分历史不完整 | 首次运行前的回看成分为近似 | 从首次运行日起每日快照；近似日期在回看页标注 |
| 个股级回补量大 | 首次可用前等待长 | 分多晚后台回补；未完成前功能降级显示「历史不足」 |
| 电脑关机错过分段 | 当日盘中不完整 | 启动时补收盘全量；盘中缺段标「未采集」 |
| 单进程内调度与 Web 争抢 | 盘中计算时页面卡顿 | 计算在线程池执行，DuckDB 读写连接分离；计算目标 1 分钟内完成 |
| 规则改动回归 | 名单质量下降不易察觉 | 47 条验收转自动化测试 + 5 个历史日金样本 + Playwright 页面用例 |
| 指数被当成买卖信号 | 用户绕过名单规则 | 指数页只显示分项与分位，不显示箭头 / 建议；风控开关是唯一影响名单的量且只暂停新增买入 |
| 提示模板文案漂移 | 出现禁用词或断言式表述 | 模板进仓库评审；测试对全部模板与全部渲染结果跑禁用词检查 |
| 命令行与主进程同时写库 | DuckDB 写冲突、文件损坏 | 文件锁 + 命令行转 HTTP 交主进程执行 |
| DuckDB 升级后旧文件不可读 | 历史全丢 | 每周自动 export；升级前 CI 演练 import |
| 本机时钟漂移 | 分段在错误时间触发 | 启动校验并警告；分段边界差分以服务器时间戳记录 |
